BoardRipper runs in the browser. Nothing is installed and nothing is uploaded; the boardview files and PDFs stay on your machine. What it needs from the browser is WebGL for the board and a JavaScript engine from 2023 or newer for everything else.

There are two web versions:

  • Main version — ripperdoc.de/boardripper/web/. Browsers from 2023 on; iPadOS 16.4 and newer.
  • Legacy version — ripperdoc.de/boardripper/legacy-web/. The same app built for older browsers, down to iPadOS 15.4. New and not yet confirmed on real devices; see below.

“current” = gets iPadOS 27 (September 2026). iPadOS 26 is the last version for the 2018 iPad Pro, iPad Air 3, iPad 8 and iPad mini 5; they keep working, they just stop updating.

Folder library needs iPadOS 18.4 or newer — that is when Apple let a web page open a folder. Before that you open boards and PDFs one at a time from Files or with the Open button; everything else is the same.

Should work means every check we can do says yes, but no one has run it on that iPad. If you have one, a short note on Discord is welcome.

Older iPads: the legacy version

ripperdoc.de/boardripper/legacy-web/ — the same BoardRipper, built so it also starts on iPadOS 15.4 to 16.3 (iPad Air 2, iPad mini 4, iPhone 7 / 6s / SE 1, and anything left on an early 16). On a current iPad it is the same as the main version.

It is new and has not been run on one of those devices yet. That is what publishing it is for: if you have one, open it, load a board, and tell me what happened.

PDF viewing may work worse than the board view. The PDF engine (pdf.js) had issues on the main version too and is being worked on; judge the legacy version by the board first.

The version badge in the toolbar reads -legacy. Installed to the Home Screen it appears as “BR Legacy”, next to the main one if you have both. The legacy build is updated by hand for now; once it is confirmed, the same changes go into the main version and this page says so.

Good to know

WebGL — the board is drawn on the GPU. Every browser in the table has it. If it is switched off (some managed company browsers do that), the board area stays empty. In Chrome, chrome://gpu shows whether WebGL is on.

Keeping the library on an iPad — Safari deletes a website’s stored data after seven days without a visit. Add BoardRipper to the Home Screen (Share › Add to Home Screen) and that rule does not apply; the library index and cached boards stay.

Two-window mode — board on one screen, schematic on another. Desktop browsers only.

Old hardware — tested on a 2020 iPad Pro and on 2012–2014 Intel laptops (HD 4000 era, 10–30 fps on big boards). On a 2 GB iPad a large Allegro or TVW board may run out of memory; the common BRD, BVR, BDV, FZ and XZZ boards are small and open fine. The touch performance setting is on by default on tablets and trades some resolution for a smooth pan.

What could be improved

  • A message instead of a blank page on a browser that is too old. The legacy version has it; the main version gets it with the next release.
  • Confirming the legacy version on 2014–2018 iPads (iPadOS 15.4 to 17.7). Every check we can do says yes; nobody has held one. Reports from real devices settle it.
  • Folder library before iPadOS 18.4 — not possible, the browser has no way to open a folder. Updating iPadOS is the fix.
  • PDF viewer on older iOS — the PDF engine (pdf.js) moves fast and its newest releases assume iOS 26. BoardRipper carries small compatibility shims so iOS 15.4 to 18 keep working, and will keep doing that.

BoardRipper should run on your device and does not?

Tell me the device, its OS version and what you see (blank page, empty board, no PDF): Discord @inwerp on the RipperDoc server, or an issue on GitHub. The same device asked for by several people moves up the list.

Desktop app: macOS 11 and Windows 10 or newer; the Legacy Mac build runs on macOS 10.15 Catalina. The Docker version is served from your NAS and follows the browser table above.
