Worklist, final check

Two changes since the last pass: readings only appear when there is a reading, and the worklist line becomes a search. Everything else is as agreed, and the row itself is still untouched.

2026-09-16 · final check before building · specimens use the real tokens from index.css

Change one · readings appear when there is something to show

The three slots no longer render on every net. A net shows only the readings it holds, as values rather than boxes, and the empty slots appear under the row you have selected — where you are about to measure something anyway.

Parts are unaffected: they never had readings. A net with nothing measured is now exactly as tall as a part, so a mixed list reads as one list.

Change two · the worklist line is a search

Clicking the line puts a cursor in it. Before you type it lists the worklists you touched most recently; type and it searches, across boards as well as this one. The menu items stay at the foot, where they were fine.

Unchanged from the agreed design

  • The row is exactly as it is. Mark cycle and its four colours, the condition flag always there to press, monospace designator, note with its peek, remove. Nothing hidden, nothing reordered.
  • Highlight stays a named control in the header, lit when on, with Copy, Wipe and delete in the menu beside it.
  • No browser dialogs. Naming happens in the search line or in the header, the way renaming already works. Wipe and delete ask inside the panel.
  • The Tools catalog is the index. Rows get counts, progress and a click; “All worklists…” goes there.
  • Real stylesheet classes so the panel follows the theme, and one row component instead of two near-identical ones.
  • The cyan selection band is untouched. Still its own review, on its own terms.
