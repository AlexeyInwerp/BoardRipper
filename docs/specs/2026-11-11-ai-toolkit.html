BoardRipper AI Toolkit

Two ways to use AI with BoardRipper. Connect: an agent you already run (Claude Code, Cursor, Codex and others) reads and drives BoardRipper over MCP. Assistant: a chat panel inside BoardRipper, using your own API key, a local model or your ChatGPT plan. Every route below is one the model vendor documents for this use. Nothing depends on a grey area.

The rules everything else follows

These hold for every part of the toolkit. A feature that would break one is not built.

1

We never touch another app's sign-in

BoardRipper does not read, copy, store or forward tokens of Claude, Codex, Gemini or any other client. It does not offer "Sign in with Claude" or "Sign in with Google" for model access. Anthropic and Google forbid this explicitly and have suspended accounts for it.

2

A subscription stays with its owner

On a NAS several people use one install. A ChatGPT sign-in or an API key belongs to the paired browser that added it, never to the install. Answering someone else's request with your plan is the "on behalf of other users" sharing OpenAI and Anthropic both forbid.

3

Subscriptions to Claude and Gemini are used through Connect

Someone with Claude Pro/Max or a Google login runs the vendor's own app (Claude Code, Claude Desktop, Gemini CLI) and connects it to BoardRipper. That is the use those apps are made for. The Assistant panel accepts Claude and Gemini only with an API key.

4

The user sees what leaves the machine

Board data and PDF text go to whichever provider the user picked. The panel names the provider on every conversation, and a local model is always offered for boards the user must not upload.

5

Changes to the board need a yes

Reading is free. Selecting, highlighting and navigating need the per-assistant can drive the board permission. Anything that edits data (worklists, notes) asks every time. Text from a PDF or a web page is treated as data, never as an instruction.

6

Re-checked before each release that touches it

Terms change. The table under "Allowed routes" carries the date it was checked and its sources. A release that changes a provider re-reads them.

A1

Recipes in one table

store/mcp-clients.ts holds each client's install method: deep link (VS Code, Cursor, LM Studio), bundle download (Claude Desktop), command (Claude Code, Codex, Gemini CLI) or config snippet (Windsurf, Zed). One more choice, All assistants on this computer, gives npx add-mcp <url> --header … --all, which writes all ten common agents at once. Formats marked "check" earlier are confirmed before they ship.

A2

No auth choices on screen

The default credential is the browser's pairing token, so an agent sees only that browser's boards. OAuth is used where the address is loopback or HTTPS. The install-wide token sits under Advanced and is served only after an explicit reveal.

A3

Connected assistants

The server records each client's name from MCP initialize. The sheet confirms the first call, then lists every assistant with its last call, its own can drive the board switch and Disconnect.

A4

Claude Desktop without Node, desktop app without files to edit

A generated .mcpb bundle carries the URL and token; Claude Desktop runs it with its own Node. The Electron app finds installed clients and writes their config itself, with a backup and the diff shown, the way JetBrains and Docker Desktop do it. A server mcp-stdio subcommand serves clients that only speak stdio.

A5

Server fixes from the review

destructiveHint: false and idempotentHint: true on the drive tools, openWorldHint: false on all, so clients stop asking before every highlight. Tool groups in the URL (?tools=board,pdf, ?read_only=1) to stay under client tool limits. A Host allow-list in front of /api/mcp* against DNS rebinding. The Claude Code skill's rules move into server instructions and prompts so every client gets them.

Part B · Assistant

A chat panel in BoardRipper, a destination on the activity rail. The Go backend runs the conversation itself, so it works the same on the NAS, in the desktop app and on an iPad. There is one tool loop with a small adapter per provider. The tools are the MCP server's own, called in-process, so Connect and Assistant can never drift apart.

B1

Providers

Anthropic, OpenAI and Google with the user's API key; Ollama and LM Studio through their OpenAI-compatible endpoint; ChatGPT plan in phase 4 through OpenAI's open-source program (our own OAuth client, a per-install host ID, the token refreshed by us, "Continue with ChatGPT" per OpenAI's UI rules, Plus/Pro only). Keys and sign-ins are stored on the backend per paired browser, mode 0600, and are never sent back to a browser.

B2

Right-click actions

On a part: Describe, Find datasheet, Find equivalent. On a pin: Where does this net come from?. Each opens the panel with a prepared question. Taken from NexusBV, which proved them useful.

B3

Repair knowledge

A hints file maps symptoms ("no backlight", "no VCCCORE") to what a technician checks first, served as MCP prompts so Connect agents get it too. A read-only Summarise this board workflow identifies the device and the board's role before anything else.

B4

What the assistant cannot do

No shell, no file writes, no network access except the provider's own web search for datasheets. No edits without a confirmation. No answers routed through another person's key or plan.

Deliberately not built

  • Running Claude Code inside BoardRipper on the user's Claude plan, whether through the Agent SDK, the ACP adapter or claude -p. All three drive the same binary the same way, and the Agent SDK docs say: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products." OpenCode (2.2.3) and Zed do it, but no public approval exists, so it is tolerated, not permitted. Revisit only with Anthropic's written OK.
  • Gemini or Antigravity on a Google login inside BoardRipper. Consumer Gemini CLI login moved to Antigravity CLI on 2026-06-18, and its terms name third-party use as a breach.
  • Reading credentials from ~/.claude, ~/.codex or ~/.gemini, for any reason.
  • One subscription answering several people's browsers on a shared NAS.
  • A BoardRipper-paid model behind the app. That would make us a reseller with our own terms to meet.

Before building

  • Phase 4: confirm on OpenAI's registration page that a self-hosted AGPL app with a Docker install qualifies as "open-source and locally hosted". If the answer is unclear, file the interest form first.
  • Phase 1: test OAuth over plain http:// on a LAN address in Claude Code and VS Code.
  • Naming: we may say BoardRipper "works with Claude Code" in plain text; we may not use Anthropic's, OpenAI's or Google's logos or names in our feature names.
