The app bar

  • Six things, in every state. Sidebar cycle, Open, search, 2-window, About, version. Switch to the PDF or Home state above: the bar does not change. Today it changes shape per tab, which is how you end up with a "Top" button lit while looking at a PDF.
  • Search takes the centre at 440px, with its shortcut shown (⌘F, already bound). It is the one control that spans board, PDFs and library, and the focused state shows why: results come back grouped by where they were found, with the same three colours the tab strip already uses for board and PDF.
  • 2-window mode becomes an icon on the right, next to About. It is a window action used once a session; it was the widest button on the bar.
  • Version chip keeps its four states — current, update available (amber dot), important (red), dev — exactly as today. The rail's Settings dot mirrors the update signal, so the chip can stay quiet.
  • No group boxes. Three quiet buttons left, three quiet buttons right, the search between. The bar loses its three inset frames and ~2px of visual weight per edge.

The board bar

  • Order is by how often you touch it. Side · rotate left/right · more transforms │ follow-PDF, scroll mode, fit │ hover info, spotlight, net lines, ghosts │ Parts, Nets · shade handle at the right end, where the Classic Mac collapse box was. The first four are new here; everything after the first separator is the bar as it exists today.
  • Side is a two-segment control with the words on it. It is the most used control in a repair session and earns its labels. Click to show; hold to peek at the other side; Shift-click for both — all three gestures are what the toolbar's Top/Bottom already does, unchanged, key F unchanged.
  • Rotate left and right stay one click. Everything rarer — 180°, mirror H/V, flip axis, butterfly, traces — lives in the ⋯ Transform menu (open it above). Mirror keeps its ⌘↑ shortcut; butterfly and traces only appear when the format has them, the same rules the toolbar applies today.
  • The shade folds the whole thing, transforms included, rolling up toward the bar's left anchor until only the handle is left. That is what makes "nothing but the board" true under C: cycle the sidebar out, fold the shade, and the app bar is all that is left.
  • Narrow panels wrap. Switch Panel width to Narrow: the labels on Side and Parts/Nets drop to icons first, and if the bar is still wider than the panel it wraps to a second row inside the same chip. No logic, no hidden controls. A priority-overflow menu is the upgrade if wrapping ever looks wrong on a real screen.
  • It is still the slot bar. Settings ▸ Board overlay can hide or reorder the new slots like any other, so someone who wants Side back on top of everything can drag it there.

How it is built

  1. Four new slots in overlay-layout.ts: sideSwitch, rotateCCW, rotateCW, transformMenu, plus a leading separator. Each renderer under components/overlay/slots/ calls the store action the toolbar button calls today — selectTop/selectBottom with the same shift and hold handling, rotateCW/CCW/180, flipHorizontal/Vertical, toggleFlipAxis, toggleButterfly, toggleTraces. No new behaviour.
  2. Layout migration, the one trap. reconcileOverlayLayout appends slots a saved layout has never seen to the end. For every existing user that would put Side after Nets. Add one rule: when none of the four new ids is present in the saved layout, insert them at the front. New installs get the default order; nobody's own arrangement is otherwise touched.
  3. Toolbar.tsx loses three groups (side, transforms, traces) and the labelled 2-window button; gains the centred search layout and the icon 2-window button on the right. About 120 lines out, 30 in.
  4. Settings ▸ Board overlay picks the new slots up from the layout automatically; only its label map needs four entries so the drag list names them.
  5. Tests. 44 call sites across 8 specs click the toolbar's Top/Bottom/rotate/traces/2-window. The new slot buttons carry the same test ids where one exists (traces-btn, two-window-toggle) and gain side-top / side-bottom / rotate-cw / rotate-ccw; the text-based hasText: 'Top' lookups migrate to those ids, the same way the sidebar tabs did. One new spec covers the slots, the menu, and the migration rule.
  6. Keyboard shortcuts, MCP drive-UI tools, and board-store do not change. Both read and write the same store; only the button's home moves.

Decisions taken, and the two still open

  • Side keeps its words. Icon-only Top/Bottom was tried in the sketch and was ambiguous with the layer icons on TVW boards. Two words cost 60px and remove a whole class of "which side am I on" mistakes.
  • Rotate gets two buttons, not one plus a menu. Repair sessions rotate in both directions constantly; hiding either behind a click is a regression.
  • The ⋯ menu groups by what it does to the board (Transform · Side · Traces) rather than by how often it is used. Rare controls need a stable home more than a clever one.
  • Open, not Upload. In the browser the file is read into memory, and the old label said so; but the Electron build already says Open, and the distinction was never something a user needed. One word everywhere.
  • Open — PDF tab. With the transforms gone, the app bar over a PDF is six quiet controls and a search box. The PDF's own controls sit in its panel header, as today. It reads as intended in the mockup; it wants one look on a real schematic before it is called done.
  • Open — the ☰ toggle. The board sidebar's ☰ stays where it is. There is a reasonable case for moving it into the board bar's right end so the whole board has one control surface; it is left alone here because the board sidebar is its own phase-2 item.
